    Chapter 1 of 14

    The big idea

    A chip is not clever. It is fast. If you understand one tiny step, you can understand the whole chip.

    Every computer has a part that follows instructions. It is called the microprocessor (a small chip that reads instructions and carries them out, one by one. It is the "brain" of a laptop or a phone. Example: the Intel or AMD chip inside a laptop). People also call it the CPU (Central Processing Unit: another name for the same "brain" part).

    Each order it follows is an instruction (one small command that the chip can do in one go. Example: "add these two numbers"). A list of instructions is a program (instructions written in order, the way a recipe is a list of steps. Example: the calculator app on your phone).

    A processor can do only a few kinds of things

    • Move a number from one place to another.
    • Calculate: add, subtract, compare, and simple logic.
    • Decide which instruction comes next. Example: "if the answer is zero, go to step 5".

    That is almost all. A video game, a video call and a UPI payment are each made of millions of these tiny moves. A modern processor does billions of them every second, so it looks like magic.

    Picture a kitchen

    Each part of a processor has one simple job. A kitchen has the same jobs.

    The recipe book, with numbered steps

    Memory (the place that stores numbers in numbered boxes. It holds the program and the data the program uses. Example: the RAM in a phone)

    Your finger on the step you are doing now

    Program counter (a tiny box inside the CPU that holds the number of the next step to do. Example: if it holds 7, the next instruction comes from box 7)

    Reading the step and understanding it

    Control unit (the manager part of the CPU. It reads each instruction and switches on the right parts in the right order. Example: for "add", it connects two numbers to the calculator part)

    Small bowls on the counter

    Register (a tiny, very fast storage box inside the CPU. Each one holds one number that the CPU is using right now. Example: while adding 5 + 3, one register holds the 5)

    Cutting and cooking

    ALU (Arithmetic Logic Unit: the calculator part of the CPU. It adds, subtracts and compares numbers. Example: it works out 5 + 3 = 8)

    A drum beating at a steady speed. You make one small move on each beat.

    Clock (a signal that ticks at a perfectly steady speed. On each tick, the whole chip moves forward by one small step. Example: a 3 GHz clock ticks 3 billion times every second)

    The cook never thinks about the whole dish. The cook only repeats one loop: read the step, understand it, do it, then move the finger to the next step. A processor runs the same loop, forever. Engineers call it fetch → decode → execute. You will watch it happen in Chapter 7.

    The whole story is a ladder

    Start at the bottom. Each rung is built only from the rung below it.

    1. 1

      A transistor (a tiny switch that is turned ON or OFF by electricity, with no moving parts. Example: a phone chip has billions of them).

    2. 2

      A logic gate (a few transistors wired together to make one simple decision. Example: "are both inputs ON?").

    3. 3

      Gates that calculate (an adder) and gates that remember (a memory cell).

    4. 4

      Parts with jobs: the ALU, the registers and the control unit.

    5. 5

      The processor, running fetch → decode → execute.

    6. 6

      A computer: the processor plus memory plus input/output (I/O: the ways a computer takes information in and sends results out. Example: a keyboard is input, a screen is output).

    Nothing magic is added at any rung. This page climbs the ladder one rung at a time.

    And the microcontroller?

    A microcontroller (one chip that holds a small processor plus its own memory and input/output parts, so it can run a machine all by itself. Example: the chip inside a washing machine) uses the same processor idea. The difference is what sits around the processor.

    Key idea

    Every processor in the world, from a TV remote to a supercomputer, is built on this same short story. Chapters 2 to 9 build the microprocessor. Chapters 10 to 12 cover where it is used and the microcontroller. Chapter 13 tests you, and Chapter 14 sums it all up.

    Chapter 2 of 14

    Bits: the only language a chip knows

    Inside a chip there are no letters, pictures or sounds. There are only wires, and each wire is either low or high.

    Every wire in a chip carries a voltage (the electric "push" on a wire, like the pressure of water in a pipe. Example: a phone battery gives about 3.7 volts). A chip cares about only two levels: low, near 0 volts, and high, near the chip's supply voltage (about 1 volt in a modern processor). We write low as 0 and high as 1.

    One 0-or-1 value is a bit (binary digit: the smallest piece of information. It can only be 0 or 1, like a light that is OFF or ON).

    Why only two levels?

    Real wires are never perfect. Their voltage wobbles a little because of heat and nearby wires. This unwanted wobble is called noise (small, random changes in a signal, like the hiss on a badly tuned radio). If a wire used 10 levels, a small wobble could turn a 6 into a 7. With only 2 levels far apart, a small wobble cannot turn a 0 into a 1. That is why chips almost never make mistakes.

    Counting with only 0 and 1

    Binary (a way of writing numbers with only two digits, 0 and 1. Example: 5 is written 101) works like normal counting, but each place is worth double the place on its right: 1, 2, 4, 8, 16, 32, 64, 128. To read a binary number, add up the places that hold a 1. Example: 0000 0101 = 4 + 1 = 5.

    A group of 8 bits is a byte (8 bits together. It can hold any whole number from 0 to 255. Example: 1111 1111 = 255).

    Key idea

    Same bits, different meanings. The pattern 0100 0001 is the number 65, the letter A, and an instruction for our toy processor, all at the same time. The bits do not know what they mean. Meaning comes only from how a part of the chip uses them. Keep this idea in mind. It explains a lot in Chapter 7.

    Real numbers

    Bigger processors work on bigger groups of bits at once. A 64-bit (able to handle 64 bits in one go) processor can hold a number as large as about 18 quintillion (18 followed by 18 zeros) in one register.

    Chapter 3 of 14

    The transistor: a switch with no hands

    A processor is billions of tiny switches. Learn how one switch works, and you have learned the most important part.

    Think of a water pipe with a tap. Water wants to flow from one end to the other, and the tap decides: flow or no flow. A transistor does the same job for electric current (a flow of electric charge through a wire, like water flowing through a pipe). The difference is that its tap is turned by electricity, not by a hand.

    A transistor has three connections:

    • Source (the end where the current comes in, like the tank side of a pipe)
    • Drain (the end where the current goes out, like the open end of a tap)
    • Gate (the control. A voltage on the gate opens or closes the path between source and drain, like turning a tap handle)

    How the gate works without touching

    Transistors are made of silicon (a material made from ordinary sand. Very pure silicon is the base of almost every chip). Silicon is a semiconductor (a material halfway between a conductor like copper and an insulator like plastic. We can control whether it lets current pass. Example: silicon).

    The gate sits on a very thin insulator (a material that blocks current, like the plastic around a wire). In modern chips this layer is only a few nanometres (a nanometre is one billionth of a metre. A human hair is about 80,000 nanometres wide) thick. So the gate never touches the silicon below it.

    When the gate gets a high voltage, its electric pull draws electrons (tiny particles with a negative charge. Moving electrons are what we call electric current) up to just under the insulator. They form a thin path called the channel (a short-lived bridge for current between source and drain. It exists only while the gate is ON). When the gate voltage goes away, the electrons drift off, the bridge disappears, and the current stops. It is a bit like a magnet pulling pins toward it from a distance.

    Key idea

    Switches can control switches. The output of one transistor can drive the gate of the next one. This one fact lets us chain switches into decisions, maths and memory. A transistor never thinks. The pattern of the wiring does all the work.

    Two kinds that work as a team

    The transistor above is an NMOS. It turns ON when its gate gets a 1. Its partner, the PMOS, does the opposite: it turns ON when its gate gets a 0. Both are MOSFETs (Metal-Oxide-Semiconductor Field-Effect Transistors. The name lists the layers you saw: a metal gate, an oxide insulator and the semiconductor below).

    Chips use NMOS and PMOS in pairs. This design is called CMOS (Complementary MOS. "Complementary" means partners that do opposite things: when one is ON, the other is OFF. So almost no current flows while nothing changes, which saves a lot of power. Example: almost every chip made today is CMOS). You will see a CMOS pair at work in Chapter 4.

    How small? How many?

    1947

    The first transistor was built at Bell Labs in the USA. It was big enough to hold in your hand.

    1971

    The Intel 4004, the first microprocessor on a single chip, had about 2,300 transistors.

    2020

    Apple's M1 chip had about 16 billion transistors.

    Today

    More than a thousand transistors could sit side by side across the width of one human hair. Each can switch ON and OFF billions of times every second.

    Where are the transistors in a processor? Everywhere. The ALU, the registers, the memory and the control unit are all transistors, wired in different patterns. Above the transistors, more than ten layers of very thin metal wires connect them, like flyovers stacked over a busy city.

    Common confusion

    "The ALU is made of transistors, but memory is made of something else." No. Every part of a processor is made of the same kind of transistors. The only difference between the parts is how the transistors are wired together.

    Logic gates: switches that decide

    Wire a few transistors together, and they can make a decision.

    In Chapter 1 you met the logic gate. Every gate follows one fixed rule. The rule is written as a truth table (a small table that lists every possible input and the output for each one).

    Key idea

    A gate does not know anything. It is just switches placed so that the output gets connected to 1 only in certain cases. The decision is in the shape of the wiring.

    Chapter 5 of 14

    Gates that calculate, gates that remember

    Every part of a processor is built from gates in one of two ways: without loops, or with loops.

    • Combinational logic (gates with no loops. The output depends only on the inputs right now. Example: an adder. Change the inputs, and the answer changes almost at once)
    • Sequential logic (gates with a loop. The output also depends on what happened before, so the circuit can remember. Example: a memory cell)

    Part 1: adding with gates

    Binary addition works like school addition, with carries. 0 + 0 = 0. 0 + 1 = 1. 1 + 1 = 10, which means "write 0, carry 1 to the next place", just as 5 + 5 = 10 in normal numbers.

    A half adder (a tiny circuit that adds two bits) needs only two gates: SUM = A XOR B, and CARRY = A AND B. Check it against the truth tables in Chapter 4. A full adder (a circuit that adds three bits: A, B, and the carry coming in from the place on its right) is two half adders plus one OR gate.

    Put full adders in a line, and each one passes its carry to the next, like falling dominoes. This is a ripple-carry adder (an adder in which the carry "ripples" from right to left, one place at a time).

    What about subtraction? The same adder does it, using a trick called two's complement (a way to write a negative number in binary: flip every bit, then add 1. Example in 4 bits: 3 = 0011, flipped = 1100, plus 1 = 1101, which means −3). Now 5 − 3 = 5 + (−3) = 0101 + 1101 = 1 0010. Drop the extra bit on the left, and you get 0010 = 2. Correct! So one adder does both jobs.

    Put an adder next to gate groups for AND, OR and comparing, and add a multiplexer (a selector circuit: several inputs come in, and a few control wires choose which one goes out, like a TV remote choosing one channel). That is an ALU.

    Part 2: remembering with gates

    How can switches remember? Make a loop. Connect two NOT gates in a circle: the output of the first goes into the second, and the output of the second goes back into the first.

    This loop is a latch (a circuit that holds one bit by feeding itself in a loop, like two friends reminding each other of a phone number again and again). A flip-flop (a latch that is allowed to change only at the exact moment of a clock tick. It waits for the beat) is the basic memory piece inside a processor. A register is just a row of flip-flops: 8 flip-flops hold 8 bits, and 64 flip-flops hold 64 bits.

    Three ways chips store bits

    6 transistors per bit

    SRAM cell

    SRAM (Static RAM: memory that holds each bit in a loop of transistors, like the latch above. It needs no refreshing) uses two NOT gates (4 transistors) plus 2 "door" transistors for reading and writing. It is very fast but takes a lot of space. It is used for registers and for the cache (a small, very fast memory inside the processor that keeps copies of recently used data, so the CPU does not wait for slow main memory. Like keeping your most-used books on your desk).

    1 transistor + 1 capacitor

    DRAM cell

    DRAM (Dynamic RAM: memory that stores each bit as a tiny electric charge, which must be topped up regularly) keeps the charge in a capacitor (a tiny "bucket" that stores electric charge. Full = 1, empty = 0). The bucket slowly leaks, so the memory chip refills every row about every 64 milliseconds (thousandths of a second). It is small and cheap, so we get many gigabytes (a gigabyte is about a billion bytes). It is used for main memory.

    electrons trapped in glass

    Flash cell

    Flash memory (memory that keeps data without power by trapping electrons on an extra "floating" gate, wrapped in insulator) keeps its bits for years with the power OFF. Writing is slower. It is used in phone storage, pen drives, SSDs and the program memory of microcontrollers.

    So memory comes in two kinds. Volatile (it forgets everything when the power goes OFF. Example: RAM) memory and non-volatile (it keeps its data without power. Example: the Flash in a pen drive) memory.

    Key idea

    Calculate = gates without loops. Remember = gates with loops. Add a clock to keep them in step, and you have everything needed to build a processor.

    Chapter 6 of 14

    Open up a real processor

    Before we run our simple processor, look at a real one. Tap any part to see what it does.

    A processor you can buy is a package (the protective case around the chip, with metal contacts that connect it to the board. Example: the square part you see on a computer's main board). Inside is the die (the small, flat piece of silicon that holds all the transistors. A laptop processor's die is often about the size of a fingernail). The package sits on the motherboard (the main circuit board of a computer. The processor, RAM and other chips plug into it). A die with its transistors and wires is also called an integrated circuit (IC, or simply a chip: many transistors and wires made together on one piece of silicon).

    The most important block on a die is the core (one complete processor inside the chip, with its own fetch, decode, registers and ALUs. Example: 8 cores are like 8 cooks in one kitchen, each following their own recipe). Many dies also hold a GPU (Graphics Processing Unit: a processor made of many small, simple cores that do the same maths on lots of data at once. Example: working out the colors of millions of pixels).

    Key idea

    Look at all the blue. A big part of a real chip is memory (caches). The ALUs are so fast that the real problem is feeding them data and instructions on time. A modern core spends more of its transistors on getting things ready than on the maths itself.

    Common confusion

    "A real chip is too complex to understand." Every block above is only a faster or smarter version of a part you will see in the next chapter: fetch, decode, registers, ALU, memory and the roads between them.

    The parts in the picture

    • PC: the program counter from Chapter 1. It holds the address (the number of a memory box, like a house number. Example: "box 14") of the next instruction.
    • IR (Instruction Register: holds the instruction that is being worked on right now).
    • Control unit with its decoder (a group of gates that turns an instruction's bits into ON/OFF signals for the right parts, like a switchboard).
    • MAR (Memory Address Register: holds the address the CPU wants to use, and puts it on the address bus) and MDR (Memory Data Register: holds the data coming from memory or going to memory).
    • Register A, the accumulator (the main working register. Results of maths collect here), and register B (a helper that gives the ALU its second number).
    • The ALU and the flags (single-bit registers that record what happened in the last calculation. Here, Z = 1 if the answer was zero, and C = 1 if the answer did not fit in 8 bits: above 255, or below 0).
    • Three groups of wires. A bus (a group of wires laid side by side that carry bits between parts. An 8-bit bus has 8 wires, one per bit, like an 8-lane road) carries bits between the CPU and memory: the address bus (carries WHERE: which memory box), the data bus (carries WHAT: the bits being moved) and the control bus (carries the ORDER: READ or WRITE, plus timing).
    • RAM (Random Access Memory: the main memory, here a separate chip. It is like a street of numbered houses where each house holds one byte. "Random access" means you can go straight to any house) with 16 boxes, and an output port (a connection through which the CPU sends data out to a device. Here it drives a small display).

    How an instruction is written

    Each instruction here is one byte. The left 4 bits are the opcode (operation code: it says WHAT to do. Example: 0010 means ADD). The right 4 bits are the operand (it says WITH WHAT. Here it is usually a memory address. Example: 1111 means box 15).

    The raw bits, like 0010 1111, are machine code (instructions as pure bits: the only thing a processor can read). The short names, like ADD 15, are assembly language (easy names for machine-code instructions, written for humans. A program called an assembler turns them into bits).       What you just saw

      • The PC said where the next instruction was.
      • The address bus carried where, the data bus carried what, and the control bus carried read or write.

      Common confusion

      "The chip reads the word LOAD." It does not. It only sees 0001. The decoder's wiring makes 0001 open certain paths. "LOAD" is a name for humans.

      Common confusion

      "Memory knows which boxes hold instructions." It does not. In program 1, box 14 holds 0000 0101 (the number 5). If a bug made the PC point to box 14, the CPU would fetch 0000 0101 and try to run it as an instruction. Many crashes, and some hacking attacks, work exactly like this.

      Key idea

      A loop is not a special machine. JUMP only changes the PC. That is all a loop, or an "if", really is.

      Chapter 8 of 14

      Memory: where everything lives

      A processor can only work on what it can reach. Memory is what it reaches.

      Address and value

      Memory is a long row of boxes. Each box has an address, and each box holds a value. "Box 14 holds 5" means 14 is the address and 5 is the value. The address says where. The value says what. Mixing up these two is the most common beginner mistake.

      How many boxes can a processor reach?

      Each address wire can be 0 or 1. With 1 wire you can name 2 boxes. Every extra wire doubles the count.

      The memory ladder

      Fast memory is expensive and needs a lot of space per bit. Slow memory is cheap. So every computer uses a little of the fast kind and a lot of the slow kind, arranged like a ladder. The right column turns the times into human time: imagine reading a register took 1 second.

      Registers1 secondInside the core · a few hundred bytes0.3 ns (1 tick)
      L1 cache3 secondsInside the core · tens of KBabout 1 ns
      L2 cache13 secondsNext to the core · about 1 to 3 MBabout 4 ns
      L3 cache40 secondsShared, on the chip · tens of MBabout 12 ns
      RAM5 minutesSeparate chips · 8 to 64 GBabout 90 ns
      SSD3 daysA separate drive · hundreds of GB to a few TBabout 80 µs

      Typical numbers for a PC. ns = nanosecond (a billionth of a second). µs = microsecond (a millionth of a second). The bars use a log scale: each equal step to the right means about 10 times more time.

      Caches work because programs have locality (the habit of using the same data, and nearby data, again and again. Example: a loop runs the same few instructions thousands of times). So most of the time, the data a core needs is already waiting in L1.

      RAM and storage are different things

      RAM is the work table. Storage (where files are kept for the long term, even with the power off. Example: an SSD or a hard disk) is the cupboard. Most computers today use an SSD (Solid State Drive: storage made of Flash memory, with no moving parts). When you open an app, its program is first copied from storage into RAM, because the CPU fetches instructions from memory through its caches. When the power goes off, the table is wiped clean, but the cupboard keeps everything.

      Where does the very first instruction come from?

      At power-on, RAM is empty. So every processor starts at a fixed address chosen by its designers, called the reset vector (the address the program counter is set to when the chip powers on or resets). That address points into a small ROM (Read-Only Memory: memory that keeps its contents without power and is rarely changed. Today it is usually Flash) chip that holds the firmware (the first program that runs at power-on. On a PC it is called BIOS or UEFI. It checks the hardware and loads the operating system from storage into RAM).

      One road or two?

      The von Neumann architecture (a design where instructions and data share one memory and one set of buses. Our toy CPU in Chapter 7 is like this) is simple and flexible. But instruction fetches and data reads must take turns on the same road. This traffic jam is called the von Neumann bottleneck.

      The Harvard architecture (a design with separate memories and buses for instructions and for data) removes that jam. Many microcontrollers use it, for example the AVR chip on an Arduino Uno board. Modern PC processors mix the two: one main RAM for everything, but separate L1 caches for instructions and for data inside each core.

      Chapter 9 of 14

      How real processors get so fast

      Our toy CPU needs 4 to 6 ticks for one instruction. A modern core finishes several instructions in a single tick. Here is how.

      1. A faster clock

      The clock signal starts in a crystal oscillator (a tiny piece of quartz crystal that vibrates at a very exact speed when powered. The same thing keeps a wristwatch accurate). A circuit inside the processor multiplies this steady beat into a much faster one.

      Clock speed is measured in hertz (Hz: ticks per second. 1 MHz = 1 million ticks per second, and 1 GHz = 1 billion ticks per second). At 3 GHz, one tick lasts about 0.33 nanoseconds. In that time, even light travels only about 10 centimetres!

      Why have a clock at all? Signals need a little time to pass through gates and settle. The clock waits just long enough, then every register saves its value at the same instant. Without it, parts would grab half-finished answers.

      Why not 100 GHz? Every switch flip uses a little energy, and that energy becomes heat. More ticks per second means more heat. Around 2005, processors hit what engineers call the power wall, at about 3 to 4 GHz. Since then, most of the extra speed has come from doing more work per tick, and from more cores.

      2. An assembly line

      Pipelining (overlapping the steps of different instructions, like an assembly line. While one instruction executes, the next one is being decoded, and the one after that is being fetched) is like doing laundry. You do not wait for the first load to be washed, dried and folded before you start washing the second load.

      Real cores have pipelines of about 10 to 20 stages. But there is a problem. What if the next instruction depends on a jump, like JZ? The core does not yet know which instruction comes next. So it guesses. This is branch prediction (the core guesses which way a decision will go, works ahead on that guess, and throws the work away if the guess was wrong. A branch is any instruction that can change the PC, like JUMP or JZ). Modern predictors are right far more than 9 times out of 10.

      3. Caches

      You saw this in Chapter 8. Keeping copies of recent data close to the core means the core rarely waits hundreds of ticks for RAM.

      4. Many instructions in one tick

      A modern core has several ALUs and can start 4 to 8 instructions in the same tick. It can even run them out of order (doing later instructions whose inputs are ready while earlier ones wait for data, then putting all results back in the right order, so the program never notices). The average number of instructions finished per tick is called IPC (Instructions Per Clock. Example: an IPC of 3 at 4 GHz means 12 billion instructions per second, from one core).

      5. More cores

      Many processors have 4 to 16 cores or more. But more cores only help when the work can be split. A single step-by-step job cannot use 8 cores, just as 8 cooks cannot boil one egg faster.

      6. Many programs "at once"

      Your phone runs dozens of apps at the same time. Or does it? Each core runs only one stream of instructions at a time. The operating system (OS: the main program that manages the hardware and runs your apps. Example: Android, Windows or Linux) switches between programs hundreds of times per second. This is called time-slicing (sharing one core between many programs by giving each one a tiny slice of time, in turn), and it is so fast that everything feels simultaneous.

      7. Different chips speak different languages

      Each processor family understands its own ISA (Instruction Set Architecture: the set of instructions and rules a family of processors understands. Examples: x86 for most Windows laptops, ARM for phones and Apple's Mac chips, and RISC-V, an open design anyone can use for free). A program built for ARM cannot run directly on an x86 chip. People write programs in languages like C, and a compiler (a program that translates code written by people into machine code for one ISA) turns them into the right bits.

      Key idea

      Work per second ≈ ticks per second × instructions per tick × number of cores (when the work can be split).

      Common confusion

      "More GHz always means faster." No. A 3 GHz chip that finishes 4 instructions per tick beats a 4 GHz chip that finishes 2. Caches and memory speed matter too.

      Common confusion

      "A 64-bit processor is 64 times faster." No. It means the registers and ALU handle 64-bit numbers in one go, and the CPU can use much bigger addresses, so it can reach more memory.

      Chapter 10 of 14

      Where microprocessors work

      Use a microprocessor when you need a general-purpose brain: big programs, many apps, a full operating system and lots of memory.

      Laptops and desktops

      Your computer

      x86 chips from Intel (Core) and AMD (Ryzen). Apple's Macs use their own ARM-based M-series chips. Jobs: browsing, coding, games, video editing.

      Phones and tablets

      Your phone

      ARM-based chips such as Qualcomm Snapdragon, MediaTek Dimensity, Apple A-series and Samsung Exynos. Each one is an SoC (see below).

      Servers and the cloud

      Data centres

      Huge chips with dozens, even close to 200, cores: Intel Xeon, AMD EPYC, and ARM chips like Amazon's Graviton. They run websites, UPI payments, video streaming and AI.

      Game consoles

      PlayStation 5 and Xbox

      Both use custom 8-core AMD x86 processors, joined with a powerful GPU.

      Cars

      Screens and driver help

      The touch-screen system and driver-assist computers use microprocessors. The brakes, airbags and windows are run by microcontrollers (Chapter 11).

      Home network

      Routers and smart TVs

      Small microprocessors that run Linux, a full operating system, to handle Wi-Fi, apps and video.

      A whole system on one chip

      Your phone's chip is an SoC (System on a Chip: CPU cores, a GPU, an AI engine, a modem for the mobile network and more, all on one die. Example: the main chip in your phone). So is it a microprocessor or a microcontroller? It is a microprocessor-type system. It runs a big OS (Android or iOS), and its main RAM is a separate chip, often stacked right on top of it. Inside, it even has a few small microcontroller-like cores for side jobs such as power control.

      Microprocessor world

      Raspberry Pi

      A small computer built around an ARM SoC with a separate RAM chip. It runs Linux, has a desktop, and can browse the web.

      Microcontroller world

      Arduino Uno

      One small microcontroller chip. No OS. It runs one program, again and again, and controls LEDs, motors and sensors directly.

      What all microprocessor systems share

      • They run an operating system and many different programs.
      • They need separate RAM and storage chips around them.
      • They are fast (GHz) but use a lot of power, from a few watts in a phone to hundreds of watts in a server.
      • They start slowly (seconds), because the OS must be loaded from storage first.

      Chapter 11 of 14

      The microcontroller: a whole computer in one chip

      The same fetch → decode → execute core, plus memory and input/output, all in one small, cheap chip.

      The core inside a microcontroller works exactly like the one you watched in Chapter 7. It has a PC, registers and an ALU, and it repeats fetch → decode → execute. The difference is everything packed around the core.

      Picture it

      A microprocessor is a powerful engine. To make a car, you must add wheels, a fuel tank and a body. A microcontroller is a complete scooter. Its engine is smaller, but everything is already attached, and it is ready to ride.

      What is packed around the core

      • Flash for the program and SRAM for the variables (from Chapter 5), plus EEPROM (Electrically Erasable Programmable ROM: a small memory for settings that must survive a power cut but change sometimes. Example: an AC remembering your last temperature).
      • GPIO (General Purpose Input/Output: pins that the program can set HIGH or LOW to switch something, or read to check something. Example: lighting an LED, or reading a button) pins.
      • An ADC (Analog-to-Digital Converter: turns a smooth voltage into a number. Example: a 10-bit ADC turns 0 to 5 volts into a number from 0 to 1023, so 2.5 V becomes about 512). It connects the analog (able to change smoothly, with any in-between value. Example: temperature, or a volume knob) world to the digital (moving in fixed steps, like 0 and 1, or whole numbers) world of the CPU.
      • Several timers (counters that count clock ticks by themselves, without the CPU. They measure time or make exact delays, like a built-in stopwatch), which can also make PWM (Pulse Width Modulation: switching a pin ON and OFF very fast. The share of time it is ON sets the average power. Example: ON 25% of the time makes a fan spin slowly or an LED look dim) signals.
      • Serial ports for talking to other chips, one bit at a time: UART (a simple link with 2 wires, one to send and one to receive. Example: talking to a GPS module or a PC), I²C (2 shared wires for many devices, each with its own address. Example: a temperature sensor and a small screen on the same 2 wires) and SPI (a fast link with 4 wires. Example: an SD card or a display).
      • An interrupt controller. An interrupt (a signal that makes the processor pause its current work at once, run a short special routine, then return to exactly where it was. Like a doorbell ringing during homework) lets the chip react to a button press immediately.
      • A watchdog timer (a safety timer that restarts the chip if the program gets stuck. The program must reset the timer regularly. If it stops doing that, the watchdog "bites"), a clock, and power control with sleep modes that use only a few microamps (a microamp is a millionth of an amp, a tiny current).

      Watch one work: a smart fan

      A sensor (a part that turns something in the real world into an electrical signal. Example: a temperature sensor gives 0.01 volts for every °C, so 30 °C gives 0.30 V) measures the room. The microcontroller reads it, decides, and drives the fan, which is an actuator (a part that makes something happen in the real world. Example: a motor, a buzzer or a light). A pin can give only a small current (about 20 milliamps), so it controls a driver transistor (a bigger, stronger transistor that lets a weak pin switch a big current, like a small key that starts a big engine), which powers the fan.

      Key idea

      When the button is pressed, the CPU does not wait for the loop to finish. The interrupt makes it save its place (the PC) on the stack (a small area of SRAM used like a pile of plates: the last thing put on is the first taken off. Here it remembers where to come back to), run the button routine, then take its place back and continue.

      Where microcontrollers work

      A microcontroller is the heart of an embedded system (a computer hidden inside a product to do one fixed job. Example: the controller in a microwave oven).

      At home

      Washing machine, microwave, AC and its remote, fridge, BLDC ceiling fan, induction cooktop, water purifier, inverter, smart bulb.

      On you

      Digital watch, fitness band, earbuds and their case, calculator, keyboard and mouse.

      In a car

      Airbags, ABS brakes, engine control, power windows, seats, lights. Many modern cars have dozens of microcontrollers.

      Health

      Glucose meter, pulse oximeter, digital thermometer, blood pressure monitor.

      Everywhere else

      Traffic lights, electricity meters, lifts, drones, 3D printers, toys, and hobby boards like Arduino and ESP32.

      Real numbers

      Arduino Uno's chip (ATmega328P): 8-bit, 16 MHz, 32 KB Flash, 2 KB SRAM, 1 KB EEPROM. The ESP32: 32-bit, up to 240 MHz, with Wi-Fi and Bluetooth built in. Tens of billions of microcontrollers are made every year, far more than microprocessors. You use dozens of them every day without seeing one.

      Chapter 12 of 14

      Microprocessor vs microcontroller

      The same brain idea, in two very different bodies.

      The one-question test

      Can the chip run its program all by itself, with only power and a couple of tiny parts? Yes → microcontroller. No, it needs separate RAM and storage chips → microprocessor.

      MicroprocessorMicrocontroller
      What it isOnly the CPU (the brain)CPU + memory + input/output in one chip
      MemoryOutside: RAM sticks, SSDInside: Flash + SRAM (+ EEPROM)
      SpeedAbout 1 to 6 GHzA few MHz to a few hundred MHz
      RAM sizeGigabytes (e.g. 8 to 32 GB)Kilobytes (e.g. 2 KB to 1 MB)
      PowerA few watts to hundreds of wattsMilliwatts; microwatts when asleep
      PriceThousands of rupees or moreFrom a few rupees to a few hundred
      SoftwareA big OS: Windows, Linux, AndroidOften bare-metal (the program runs directly on the hardware, with no operating system), or a tiny RTOS (Real-Time Operating System: a small OS that promises to react within a fixed time)
      JobGeneral purpose: many kinds of tasksOne fixed job, again and again
      TimingFast on average, but the OS may pause a programVery predictable, down to the microsecond
      Start-upSeconds (loads an OS)Milliseconds (the program is already in Flash)
      ExamplesLaptop, phone, server, game consoleWashing machine, remote, Arduino, car airbag

      The power-on story

      Laptop (microprocessor)

      1. Power ON. The PC jumps to the reset vector.
      2. Firmware runs from a ROM chip on the board.
      3. It checks the RAM and finds the SSD.
      4. It copies the OS from the SSD into RAM.
      5. The OS starts. Then your apps start. Total: seconds.

      Washing machine (microcontroller)

      1. Power ON. The PC jumps to the reset vector, inside its own Flash.
      2. Your program runs. Done, in milliseconds.

      That fast, predictable reaction is what real-time (must react within a fixed, guaranteed time, every single time) means. An airbag controller must decide within a few tens of milliseconds of a crash. "Usually fast" is not good enough. It must be fast always. A microcontroller running one simple program, with no big OS to pause it, is perfect for this.

      Choose like an engineer

      Pick a microprocessor when you need

      • a screen with many apps
      • internet browsing and video
      • gigabytes of memory
      • a full operating system

      Pick a microcontroller when you need

      • to read sensors and drive motors
      • months on a small battery
      • exact, guaranteed timing
      • a very low cost per product

      Most products use both

      A phone has a big SoC for apps, plus small microcontrollers for touch, power and sensors. A car has a few powerful processors for screens and driver help, and dozens of microcontrollers for brakes, airbags and windows.

      Chapter 14 of 14

      Ten rules that explain every processor

      If you can explain each rule in your own words, with an example, nobody can shake your understanding.

      1. A transistor is a switch turned ON or OFF by a voltage. Switches can control other switches.

      2. A few transistors make a gate. Gates make simple decisions on bits.

      3. Gates without loops calculate (adders, the ALU). Gates with loops remember (latches, flip-flops, registers).

      4. Everything is bits: numbers, letters, pictures, and instructions too. Meaning comes only from how the bits are used.

      5. Memory is a row of numbered boxes. The address says where. The value says what.

      6. A processor repeats one loop forever: fetch → decode → execute.

      7. The PC decides what runs next. A jump only changes the PC. That is how loops and "if" work.

      8. Buses carry the bits: the address bus carries where, the data bus carries what, the control bus carries read or write.

      9. The clock keeps every part in step. Real chips get fast with quick ticks, more work per tick, caches and many cores.

      10. Microprocessor = the brain alone, with memory and I/O outside. Microcontroller = brain + memory + I/O in one chip, built to control one machine.
